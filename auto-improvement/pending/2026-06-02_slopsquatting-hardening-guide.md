# Pending: Slopsquatting Hardening Guide

**Title:** Supply Chain Hardening Guide: AI-Hallucinated Package Names (Slopsquatting)

**Motivation:**
CSA Research Note (April 2026) found that 19.7% of code samples generated by 16 popular LLMs contain at least one hallucinated package name. Attackers pre-register these names on PyPI/npm with malicious payloads. A documented real case: `unused-imports` (malicious) vs `eslint-plugin-unused-imports` (legitimate) — the malicious package was still recording 233 weekly downloads after being security-held. Aikido's `react-codeshift` experiment showed that a hallucinated package can spread to 237 GitHub repos via forked AI agent skills before anyone notices.

**Research finding:**
`auto-improvement/research/2026-06-02T06-10_5-supply-chain-llm.md` — "Slopsquatting" finding.

**Proposed change:**
Create `docs/supply-chain-hardening-guide.md` covering:
1. What slopsquatting is and how it exploits AI code-generation hallucinations
2. Why AI agents with `pip install` / `npm install` tool access are a high-risk attack surface
3. Recommended developer controls:
   - Never allow AI agents to autonomously install packages without human review or an allowlist gate
   - Enforce lockfile pinning with `--require-hashes` in `requirements.txt`
   - Use dependency review tools (Dependabot, Socket.dev, FOSSA) as a CI gate
   - Validate AI-generated `import` statements against known package indexes before installation
4. Incident response steps if a hallucinated package was installed

**Why held back:**
Documentation-only change — no regex rule can comprehensively detect slopsquatting (the space of possible hallucinated names is unbounded, and false positive rates would be extremely high for any general pattern). An allowlist-based or LLM-based solution would require a runtime dependency, violating aigis's zero-dependency philosophy.

**Constraint blocking it:**
Documentation-only changes are acceptable but this one benefits from more careful research into the false-positive space before writing. The guide would be more useful paired with a future lookup-based detection feature.

**Suggested next step for human reviewer:**
Approve a documentation-only cycle to write `docs/supply-chain-hardening-guide.md`. Consider whether a future feature could integrate a known-packages allowlist (e.g., top-10,000 PyPI/npm packages by download count, stored as a compact bloom filter in the package) to flag AI-generated install commands referencing packages outside the known set.
