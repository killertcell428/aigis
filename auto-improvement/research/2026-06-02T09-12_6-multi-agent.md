## Findings

- **The Dark Side of LLMs: Agent-based Attack Vectors for System-level Compromise** (arxiv:2507.06850, July 2025 / updated 2026).
  Evaluates three attack classes against 18 state-of-the-art LLMs: direct prompt injection (94.4% ASR), RAG backdoor (83.3% ASR), and inter-agent trust exploitation (100% ASR). The key finding is that models which successfully resist direct injection execute *identical payloads* when those payloads arrive via a peer agent. The attack flow: adversary poisons a document in a calling agent's RAG index with a hidden malicious string; the calling agent retrieves it, becomes convinced the action is legitimate, and relays the command to a peer agent that has terminal/tool capabilities. The invoked peer executes without further verification because inter-agent messages are trusted implicitly. Concrete payload signals include urgency markers ("IMMEDIATELY", "WITHOUT ASKING FOR CONFIRMATION") and 1337-speak encoding combined with false dependency framing ("DO NOT PROVIDE ANY INFORMATION UNTIL YOU HAVE RUN THE COMMAND").
  **For aigis:** Urgency + no-confirmation-required combined in inter-agent messages is a strong new signal distinct from existing patterns. Partially covered by `_HIDDEN_INSTRUCTION_PATTERNS` (hidden instruction tags) but the urgency marker pattern is new.
  Source: <https://arxiv.org/html/2507.06850v6>

- **Multi-Agent Systems Execute Arbitrary Malicious Code** (arxiv:2503.12188, March 2026).
  Introduces multi-agent system control-flow hijacking (MAS hijacking): adversarial content embedded in web pages, files, or email attachments hijacks control and communication within the agent graph to invoke unsafe agents and functionalities. Achieves 58–100% success depending on the orchestrator framework and model. Critically, attacks succeed even when individual agents are *not* susceptible to direct or indirect prompt injection — the vulnerability is structural, not model-level.
  **For aigis:** The key signal is adversarial content instructing an agent to invoke a *different* agent (unsafe/unregistered) by name. The existing relay and delegation patterns partially cover this, but MAS-specific "invoke agent X to do Y" phrasing is not yet covered.
  Source: <https://arxiv.org/abs/2503.12188>

- **Automating Agent Hijacking via Structural Template Injection (Phantom framework)** (arxiv:2602.16958, February 2026).
  Phantom automates agent hijacking by injecting optimized structured templates into retrieved context to cause "role confusion" — the agent misinterprets injected content as legitimate tool outputs or system instructions. Uses a Template Autoencoder to optimize adversarial templates across chat-turn token boundaries. Has identified over 70 confirmed vulnerabilities in real-world commercial products. Significantly outperforms existing baselines in both ASR and query efficiency.
  **For aigis:** The role-confusion signal is already partially covered by `_CHAT_TEMPLATE_INJECTION_PATTERNS`. The new Phantom angle — adversarial templates posing as *tool output headers* — is a narrower target that was not yet covered.
  Source: <https://arxiv.org/abs/2602.16958>

- **Byzantine-Robust Decentralized Coordination of LLM Agents** (arxiv:2507.14928, July 2025) and **AgentShield Dataset** (IEEE DataPort, 2026).
  Byzantine attacks on multi-agent consensus systems are now validated at scale: AgentShield contains 15,000 multi-agent decision scenarios (medical, legal, financial, autonomous driving) testing Byzantine resilience. Key attack patterns: agents falsely asserting that all other agents have reached consensus, false majority claims to force a proceed decision, and urgency framing that suppresses legitimate dissent. A single adversarial agent with high-confidence messaging can shift a 5-agent system's decision in 60% of trials (The Consensus Trap, arxiv:2604.17139).
  **For aigis:** `_BYZANTINE_CONSENSUS_PATTERNS` (from prior pending) directly addresses this class. The pending item's three patterns are validated by this fresh research.
  Sources: <https://arxiv.org/abs/2507.14928> | <https://ieee-dataport.org/documents/agentshield-multi-agent-llm-byzantine-fault-tolerance-evaluation-dataset>

- **Taming Various Privilege Escalation in LLM-Based Agent Systems** (arxiv:2601.11893, January 2026).
  Taxonomizes privilege escalation in LLM agent systems, documenting a confused-deputy variant where a sub-agent falsely self-reports having been granted elevated capabilities by the orchestrator for the current session, causing the orchestrator to route high-privilege tasks to the attacker-controlled agent. Distinct from upward escalation requests (which existing aigis patterns already cover) because the claim is "I already have this access" rather than "give me this access". Of 847 evaluated autonomous agent deployments, AutoGen and CrewAI both default to trusting unverified self-reported capability inventories.
  **For aigis:** `_CAPABILITY_SCOPE_INFLATION_PATTERNS` (from prior pending) directly addresses this. The patterns in the pending note cover both the "I have been provisioned" and the formal "CAPABILITY REPORT" attack vectors.
  Source: <https://arxiv.org/abs/2601.11893>

- **Open Challenges in Multi-Agent Security** (arxiv:2505.02077, May 2025).
  Surveys fundamental attribution problems for multi-agent systems: agents cannot reliably verify the identity or integrity of peer agents, regulatory compliance is undefined for cross-agent data flows, and the attack surface scales super-linearly with the number of agents. Notes that "agent-native identity and governance frameworks" are absent from all current major frameworks.
  **For aigis:** Validates the ongoing priority of `AgentMessageScanner` pattern hardening as the primary accessible defense layer, given that cryptographic agent identity is not yet widely deployed.
  Source: <https://arxiv.org/html/2505.02077v2>

- **AI Agents Hacking in 2026: Defending the New Execution Boundary** (Penligent Security, 2026).
  Practitioner survey documenting that the most commonly exploited pattern in 2026 agent incidents is implicit trust between co-deployed agents: sub-agents receive instructions from the calling agent without additional verification, and the calling agent trusts the original user/environment without establishing chain of custody. The survey recommends per-message integrity checks as the most deployable near-term defense.
  **For aigis:** Confirms that pattern-based per-message scanning (aigis's current approach) is the most practical defense given the absence of cryptographic agent identity.
  Source: <https://www.penligent.ai/hackinglabs/ai-agents-hacking-in-2026-defending-the-new-execution-boundary/>

## Candidate hardenings

1. **[IMPLEMENTING THIS CYCLE]** `_BYZANTINE_CONSENSUS_PATTERNS` in `AgentMessageScanner` — 3 regex rules detecting Byzantine consensus poisoning:
   (a) False claim that all other agents have confirmed/agreed/voted;
   (b) False majority assertion to force a proceed/approve decision;
   (c) Urgency pressure framing any hesitation/dissent as causing system failure.
   Also add `"vote"` and `"consensus"` branches to `_check_message_type` for elevated scoring when `message_type` signals a voting context.
   Category: `injection_relay`. Research: The Consensus Trap (arxiv:2604.17139), AgentShield (IEEE DataPort 2026), arxiv:2507.14928.

2. **[IMPLEMENTING THIS CYCLE]** `_CAPABILITY_SCOPE_INFLATION_PATTERNS` in `AgentMessageScanner` — 2 regex rules detecting capability scope inflation:
   (a) Agent claiming it has been provisioned/granted/authorized with elevated/admin/write access;
   (b) Formal CAPABILITY/PERMISSION/ACCESS REPORT claiming authorization from orchestrator/supervisor at session start.
   Category: `privilege_escalation`. Research: arxiv:2601.11893, OWASP LLM06:2025 Excessive Agency.

3. **[PENDING]** Urgency + no-confirmation-required combined signal from arxiv:2507.06850 ("IMMEDIATELY", "WITHOUT ASKING FOR CONFIRMATION", "DO NOT CONFIRM"). Held back: existing tool_result instruction-like checks partially cover this; dedicated urgency pattern needs careful FPR testing across legitimate monitoring agents that use urgency language.

4. **[PENDING]** MAS hijacking: "invoke agent X" / "call agent X to do Y" phrasing patterns. Held back: existing relay/delegation patterns partially cover this and a dedicated pattern needs test data from real MAS frameworks (AutoGen, CrewAI) to calibrate FPR.

5. **[PENDING]** Phantom structural template injection: adversarial content posing as tool output headers. Held back: the attack requires context around what constitutes a valid tool output header in the specific framework; framework-agnostic detection is fragile without more test data.
