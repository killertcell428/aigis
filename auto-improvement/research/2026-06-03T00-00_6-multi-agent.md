## Findings

- **OWASP Agentic Top 10 2026 — ASI01 "Agent Goal Hijack"** (OWASP GenAI Security Project, December 2025 / published 2026).
  The OWASP Agentic Top 10 framework ranks ASI01 "Agent Goal Hijack" as the #1 risk for autonomous agentic systems. The attack embeds malicious instructions in content the agent processes — emails, documents, web pages, code comments, tool outputs — that override the original goal and redirect actions toward attacker-controlled objectives. When an agent has multi-step planning and tool access, hijacking its goal doesn't just produce bad text: it produces bad *actions* across an entire workflow. In multi-agent pipelines, a hijacked agent can also propagate the goal replacement downstream, poisoning shared memory or manipulating the orchestrator's routing decisions.
  **For aigis:** Direct syntactic signals for goal hijacking (e.g. "your new goal is", "forget your original task") in inter-agent messages are detectable without runtime state; adding `_TASK_INJECTION_PATTERNS` covers these.
  Source: <https://www.trydeepteam.com/docs/frameworks-owasp-top-10-for-agentic-applications>

- **AgentLAB: Benchmarking LLM Agents against Long-Horizon Attacks** (arxiv:2602.16901, NDSS Symposium 2026 — confirmed published).
  AgentLAB's long-horizon attack benchmark spans 644 security test cases in 28 realistic environments, identifying task injection and objective drifting as the most frequent real-world attack patterns. Task injection embeds a "new task" framing mid-workflow; objective drifting gradually shifts the agent's goal across multiple turns. Both attack types use recognizable syntactic patterns: explicit "new goal:", "updated objective:", or "forget your original task" framing in peer-agent messages and tool results.
  **For aigis:** Validates `_TASK_INJECTION_PATTERNS` as covering the two most common long-horizon attack types. Measured high per-attempt impact for intent hijacking (worst case) and highest frequency for task injection and objective drifting.
  Source: <https://arxiv.org/abs/2602.16901>

- **CoT Forgery — Chain-of-Thought Hijacking via Role Confusion** (arxiv:2603.12277, 2026).
  CoT Forgery is a zero-shot attack that injects fabricated reasoning traces (structured as the model's own chain-of-thought) into user prompts or tool outputs. The model mistakes the forged reasoning for its own analysis, then acts on the fabricated conclusions. Achieves 60% attack success rate against frontier models (near-zero for controls). The attack works because LLMs perceive text sources based on linguistic characteristics rather than actual role labels — forged `<thinking>` blocks and structured analysis text occupy the same representational space as authentic reasoning. The degree of role confusion predicts attack success before the model generates any output.
  **For aigis:** Detecting `<thinking>` / `<reasoning>` XML tags embedded in tool_result messages or agent content would catch forged CoT artifacts. However, false-positive risk is high (reasoning frameworks legitimately emit these tags) — deferring as a pending idea; a scoped detector checking for these tags *followed by imperative follow-on instructions* is the safer approach.
  Source: <https://arxiv.org/abs/2603.12277>

- **ObliInjection: Order-Oblivious Multi-Source Prompt Injection** (arxiv:2512.09321, NDSS Symposium 2026, published February 2026).
  ObliInjection is the first prompt injection attack designed for agents that aggregate input from multiple independent data sources (e.g., a RAG pipeline pulling from several document chunks). Existing attacks either assume the attacker controls all sources or require knowing the segment ordering. ObliInjection optimizes the injected segment using an "order-oblivious loss" (orderGCG algorithm) so that the payload succeeds regardless of where the contaminated chunk lands in the assembled context. Effective even when only 1 out of 6–100 segments is contaminated, across 12 LLMs and 3 diverse datasets.
  **For aigis:** ObliInjection payloads are semantically identical to regular prompt injection — the innovation is in how the attacker crafts the payload, not in the payload's surface syntax. Existing aigis injection patterns already cover the injection directive surface. The key implication is that multi-source RAG pipelines are more vulnerable than previously assumed, reinforcing the importance of per-chunk scanning before assembly.
  Source: <https://arxiv.org/abs/2512.09321>

- **Real-world incident: Moltbook platform breach (January–March 2026)**.
  The Moltbook agent social network (1.5 million autonomous AI agents, 17,000 human operators) had an unsecured database that allowed any attacker to hijack any agent. Security researchers at 404 Media identified 506 prompt injections spreading virally through the agent network before the vulnerability was patched. This is the first publicly documented large-scale viral prompt injection incident across a multi-agent deployment. The propagation mechanism mirrors the "Prompt Infection" (arxiv:2410.07283) self-replication pattern already covered by `_SELF_REPLICATION_PATTERNS` in aigis.
  **For aigis:** Validates self-replication detection as a real-world concern. Incident also underscores the value of scanning *every* inter-agent message, not just messages from untrusted senders.
  Source: <https://aiautomationglobal.com/blog/ai-agent-security-identity-crisis-enterprise-2026>

- **Authorization propagation failures in multi-agent systems** (Adversa AI / academic, 2026).
  Research documents a structural vulnerability distinct from prompt injection: in multi-agent systems, authorization does not automatically propagate between agents even when prompt injection is solved. 45.6% of enterprises use shared API keys for agent-to-agent authentication, creating no individual accountability. An attacker who compromises one agent can impersonate others without any injected text, since all agents share the same credential. OWASP ASI03 ("Identity & Privilege Abuse") and ASI07 ("Insecure inter-agent communication") both address this class. Detection at the message layer is limited — this is primarily an identity governance problem requiring architecture-level controls rather than regex-based scanning.
  **For aigis:** The `AgentTopology` module already tracks agent roles and communication edges; adding a check for unexpected credential-sharing patterns or anomalous source IDs is a future hardening direction. Deferred as pending.
  Source: <https://adversa.ai/blog/top-agentic-ai-security-resources-june-2026/>

- **Structural Template Injection — automating agent hijacking** (arxiv:2602.16958, 2026).
  Automating Agent Hijacking via Structural Template Injection optimizes malicious structured templates (JSON/YAML/table fragments) injected into retrieved content to maximize role confusion and goal hijacking. By injecting structured artifacts styled like system prompts, tool-call schemas, or agent configuration objects, the attacker causes the agent to reinterpret the injected content as legitimate orchestrator instructions. The attack generalizes across RAG systems, multi-agent routers, and tool-use pipelines.
  **For aigis:** JSON/YAML-injected system-prompt-like structures with role tokens or system keys are a detectable signal. The existing `_HIDDEN_INSTRUCTION_PATTERNS` catches XML-style tags; structured-data template injection (e.g., `{"role": "system", "content": "ignore..."}`) could be a future rule. Deferred as pending.
  Source: <https://arxiv.org/abs/2602.16958>

## Candidate hardenings

1. **[IMPLEMENTED THIS CYCLE]** `_TASK_INJECTION_PATTERNS` in `AgentMessageScanner` — 3 regex rules detecting task injection / objective drifting (OWASP ASI01):
   (a) explicit goal/objective/directive overwrite framing: "your new/updated/real/true/actual/revised goal is";
   (b) goal erasure imperative: "forget/ignore/disregard/abandon/override/replace your current/previous/original task/goal/instruction";
   (c) Japanese variants of goal overwrite.
   Category: `injection_relay`. Research: OWASP ASI01, AgentLAB (arxiv:2602.16901, NDSS 2026).

2. **[PENDING]** CoT Forgery detector: `<thinking>` / `<reasoning>` XML tags in tool_result messages combined with imperative follow-on instructions. Held back: false-positive risk (reasoning frameworks legitimately emit these tags); requires message-type scoping and a two-part match pattern that needs careful calibration.

3. **[PENDING]** Structural template injection: JSON/YAML snippets with a `role: system` key or `system_prompt` key embedded in tool results or agent messages. Held back: high false-positive risk in data-processing agents that legitimately handle configuration objects.

4. **[PENDING]** Authorization propagation gap documentation: a hardening guide explaining why shared API keys between agents are a structural risk and how to implement scoped per-agent credentials. Held back: documentation-only, no code change needed; defer to a `compliance-regulation` or `incident-postmortems` cycle.
