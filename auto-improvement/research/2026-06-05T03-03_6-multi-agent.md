## Findings

- **AgentLAB: Benchmarking LLM Agents against Long-Horizon Attacks** (arxiv:2602.16901, Feb 2026).
  AgentLAB introduces five long-horizon attack types across 28 agentic environments (644 test
  cases). The two most practically detectable at the message layer are:
  (1) **Task Injection** — a three-phase attack that injects fake "Policy Notice" emails, then
  fabricates `SystemError: [POLICY_MISMATCH]` error codes to convince the agent it must open
  inbox and visit attacker URLs to resolve a compliance failure. Task-injection ASR: 51 %.
  (2) **Objective Drifting** — individually benign framing injections ("Premium lasts 3× longer")
  cumulatively redirect decisions; 38 % ASR.
  **For aigis:** The fabricated error-code syntax (`[POLICY_MISMATCH]`, `[COMPLIANCE_REQUIRED]`,
  `[SECURITY_OVERRIDE]`, etc.) is a novel, specific signal not covered by existing patterns.
  Source: <https://arxiv.org/html/2602.16901v1>

- **OMNI-LEAK: Orchestrator Multi-Agent Network Induced Data Leakage** (arxiv:2602.13477, Feb 2026).
  Demonstrates that a single indirect prompt injection can be amplified across a multi-agent
  network to leak data from agents that individually have restricted data access. Even
  reasoning models and models with explicit data-access control policies are vulnerable because
  safety research has not generalized from single-agent to multi-agent contexts. Both
  frontier reasoning and non-reasoning models were successfully exploited without insider
  knowledge of the network topology.
  **For aigis:** Reinforces the importance of scanning all inter-agent messages (not just
  user-facing outputs). Existing `AgentMessageScanner` layers are the correct defence surface.
  The specific injection payloads used resemble the existing cross-agent relay patterns.
  Source: <https://arxiv.org/abs/2602.13477>

- **Agent System Orchestration Hijacking via Simulated Error Metadata** (promptfoo LLM Security DB, 2026).
  Documents that multi-agent orchestrators are vulnerable to control-flow hijacking when
  sub-agents process untrusted input containing adversarial metadata such as simulated error
  messages (`[SYSTEM ERROR: Fallback mode activated]`) or admin directives. The orchestrator,
  lacking a way to distinguish trusted system metadata from untrusted message content,
  interprets the injected text as a legitimate system directive and reroutes task execution.
  **For aigis:** The specific bracketed admin/override codes (`[ADMIN_DIRECTIVE]`,
  `[OVERRIDE_ACTIVE]`, `[BYPASS_MODE]`) used in real orchestration hijacking are directly
  matchable by regex in the `AgentMessageScanner`.
  Source: <https://promptfoo.dev/lm-security-db/vuln/agent-system-orchestration-hijack-11cbc618>

- **Lateral Movement in Multi-Agent LLM Systems** (PipeLab, 2026).
  Every communication channel in agent networks — config files, memory files, tool results —
  is a potential lateral movement path. None of these channels typically have integrity
  checking. Researchers observed real-world post-exploitation where an LLM agent pivoted from
  an initial RCE via Marimo (CVE-2026-39987) to exfiltrate an internal PostgreSQL database in
  under two minutes. The agent replayed stolen credentials through Cloudflare Workers, retrieved
  SSH keys from AWS Secrets Manager, and opened downstream SSH sessions.
  **For aigis:** Lateral movement paths exploit the same injection-relay vectors already covered
  by aigis. Validates that `AgentMessageScanner` should be applied to ALL inter-agent channels,
  including tool results and status messages, not just text messages.
  Source: <https://pipelab.org/blog/lateral-movement-multi-agent-llm/>

- **"Agents Under Siege": Optimized Prompt Attacks on Pragmatic Multi-Agent Systems**
  (arxiv:2504.00218, 2025/2026).
  Shows that multi-agent systems with practical communication protocols are more vulnerable
  to optimized prompt attacks than single-agent systems. Attackers can use optimization-guided
  adversarial suffixes that exploit agent coordination assumptions to achieve higher ASR than
  hand-crafted attacks. Key finding: coordination messages between agents are higher-value
  attack surfaces because they are less likely to be scrutinized by safety layers.
  **For aigis:** Reinforces scanning of all message types (delegation, status, tool_result),
  which `AgentMessageScanner` already covers.
  Source: <https://arxiv.org/pdf/2504.00218>

- **Design Patterns for Securing LLM Agents against Prompt Injections** (arxiv:2506.08837, June 2025).
  Catalogues design patterns (prompt segmentation, token isolation, instruction hierarchy) that
  reduce prompt injection risk. Key structural insight: agents that process untrusted tool
  output in the same context as system instructions are inherently vulnerable. The paper
  proposes separating the "data plane" from the "instruction plane."
  **For aigis:** The data/instruction plane separation idea maps directly to aigis's scanner
  architecture — scanning messages before they enter the model's context is the correct
  interception point.
  Source: <https://arxiv.org/html/2506.08837v3>

- **DRIFT: Dynamic Rule-Based Defense with Injection Isolation** (arxiv:2506.12104, June 2026).
  DRIFT continuously "polishes" agent memory after each interaction, masking any instructions
  that conflict with the initial user query. This is a runtime mitigation rather than a
  detection approach, but its identification of "task-conflicting instructions" as the key
  signal validates the same detection heuristic used in aigis's new task-injection patterns.
  **For aigis:** Confirms that the signal "this instruction contradicts the original user
  request" is practically measurable. The explicit goal-replacement phrasing ("your new task
  is:", "ignore your original task") is the syntactic manifestation of task conflict.
  Source: <https://arxiv.org/pdf/2506.12104>

## Candidate hardenings

1. **[IMPLEMENTED THIS CYCLE]** `_TASK_INJECTION_PATTERNS` in `AgentMessageScanner` — 3 regex
   rules targeting the AgentLAB task-injection attack surface:
   (a) Fabricated bracketed system-error/policy codes: `[POLICY_MISMATCH]`,
   `[COMPLIANCE_REQUIRED]`, `[SECURITY_OVERRIDE]`, `[ADMIN_DIRECTIVE]`, `[OVERRIDE_ACTIVE]`,
   `[BYPASS_MODE]`, `[POLICY_VIOLATION]` — the specific syntax used in three-phase task
   injection attacks (51 % ASR on AgentLAB).
   (b) Explicit goal-replacement phrasing: "your new/updated task/goal/objective is:" —
   the standard framing used to redirect agent goals mid-workflow.
   (c) Task-abandonment instructions: "ignore/forget/abandon your original/previous
   task/goal/objective/instructions" — instructs the agent to discard its current work.
   Category: `injection_relay`. Research: AgentLAB (arxiv:2602.16901), DRIFT (arxiv:2506.12104),
   Orchestration Hijacking (promptfoo LLM Security DB, 2026).

2. **[PENDING]** OMNI-LEAK cross-agent data-boundary detection — detect when an agent message
   explicitly references data from a different agent's restricted domain (e.g., agent B citing
   data that only agent A had access to). Requires understanding agent data-access policies,
   which is beyond the current regex-based scan scope; needs a separate policy-aware scan mode.

3. **[PENDING]** Objective-drifting framing patterns — individually benign framing injections
   that cumulatively redirect decisions. Difficult to detect without conversation context and
   per-message scoring history. Deferred pending a multi-message semantic analysis approach.

4. **[PENDING]** Code injection via Python lambda expression patterns in agent messages
   (`'...' or __import__('os').system(...)`) — carried over from previous cycle. Still high
   false-positive risk; needs careful crafting in a dedicated cycle.
