## Summary

### What was researched
Seven findings covering: SATA masked-keyword task-linkage jailbreak (ACL 2025), Crescendo and
AutoAdv multi-turn escalation attacks, GCG-variant token-level adversarial suffix attacks, indirect
system-prompt extraction via refusal quotes, and two recent LLM-framework CVEs (CVE-2026-42208,
CVE-2026-33626).

### What was implemented
Added one new detection pattern `jb_task_masking` to `JAILBREAK_ROLEPLAY_PATTERNS` in
`aigis/filters/patterns.py`. Added 9 new tests in `tests/test_jailbreak_patterns.py`.

### What changed for users
Aigis now detects the SATA (Simple Assistive Task Linkage) jailbreak technique: prompts that
use bracket-notation placeholders ([MASK], [BLANK], [REDACTED], etc.) to hide harmful keywords,
combined with fill-in-the-blank task instructions. Previously, content classifiers scanning for
explicit harmful terms would miss these inputs because the harmful keyword is absent from the raw
text. Score 55 (medium risk).

### What was only documented or deferred
- Multi-turn escalation patterns (Crescendo, AutoAdv): require cross-turn state tracking, not
  feasible in single-turn filter. Deferred.
- Token-level GCG adversarial suffix attacks: require embedding-space analysis. Out of scope.
- Output-side refusal quote extraction: deferred to pending (needs false-positive scoping work).

## Implementation caveats
- The `jb_task_masking` score (55) is intentionally mid-range. NLP practitioners discussing
  BERT masked language modeling could occasionally trigger the pattern if they also include
  fill-in task language; score 55 accumulates with other signals but does not alone block.
- Bracket placeholders from legitimate document templates (e.g., [BLANK] in a form) won't
  trigger alone — the fill-in task instruction is also required.
