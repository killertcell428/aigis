## Summary

**Researched:** Payload-splitting, translation-framing prompt extraction, refusal suppression,
policy-config spoofing (Policy Puppetry), FlipAttack text reversal, MetaBreak special-token
injection, Deceptive Delight camouflage, and Doublespeak codeword substitution.

**Implemented:**
- `jb_payload_splitting` — detects step-enumerated decomposition attacks where benign numbered
  steps precede a harmful request concealed in a later step ("Speak Easy", ICML 2025,
  arxiv:2502.04322). Score 55.
- `jb_translation_extraction` — detects translation-framing system-prompt extraction: requests
  to translate/rewrite/render system instructions into a foreign language. Score 65. Covers a
  gap not addressed by `pi_system_prompt_leak` (direct disclosure) or `jb_structured_extraction`
  (JSON field requests).

**Deferred to pending:** refusal suppression, policy-config spoofing, FlipAttack decoding
instruction, MetaBreak special token injection, Doublespeak codeword substitution.

## User-Visible Impact
Two new jailbreak detection rules added. Agents and AI systems using aigis's input filter will
now receive risk signals when:
- A multi-step numbered query embeds known-dangerous content (specific drugs, weapons, malware
  types) in a later step after benign framing.
- A request asks the model to translate or rewrite its system instructions into a foreign
  language (translation-framing extraction attack).

## Implementation Caveats
- `jb_payload_splitting` uses a specific dangerous-term list (same substances/malware types as
  `jb_academic_research_bypass`) to keep false positives low. General terms like "synthesis" or
  "vulnerability" were excluded to avoid false positives on education/security content.
- `jb_translation_extraction` matches explicit system-prompt terms combined with translation
  verbs + language names. Requests to translate user-provided documents or messages are not
  matched (confirmed by false-positive tests).
