## Summary

### What was researched

Seven new agent-tool-abuse techniques identified across May 2026 publications:
1. MCP sampling inversion-of-control injection (Palo Alto Unit42, May 2026)
2. Chat-template role-token forging in tool outputs (ChatInject, ICLR 2026, arxiv:2509.22830, 52% ASR)
3. OAuth/bearer token extraction via injected instruction (CVE-2025-6514, 558k+ downloads)
4. MCP stdio architecture RCE (OX Security, CVE-2026-30623, 200k+ instances)
5. ToolHijacker S-sequence capability stacking (NDSS 2026, arxiv:2504.19793, 96.7% ASR)
6. ETDI tool squatting formal taxonomy (arxiv:2506.01333, Anthropic-affiliated)
7. Semantic Kernel code-REPL injection (CVE-2026-25592/26030, Microsoft Security Blog May 7, 2026)

### What was implemented

Three new `DetectionPattern` entries added to `MCP_POISONING_PATTERNS` in `aigis/filters/patterns.py`:

1. **`chat_template_role_injection`** (score 75, input/output filter) — Detects two or more LLM role-separator tokens (`<|user|>`, `[INST]`, `###Human:`, `<|start_header_id|>user<|end_header_id|>`, etc.) appearing inside tool outputs or retrieved content, signaling the ChatInject attack (ICLR 2026). Closing the output-filter gap left by the H4 heuristic in `mcp_scanner.py` (which only covered tool descriptions).

2. **`mcp_token_extraction_request`** (score 70, input/output filter) — Detects instructions directing the agent to print/reveal/output its current access token, bearer token, OAuth credential, JWT, or session token. Targets the token-extraction sub-attack documented in CVE-2025-6514 (critical severity, 558k+ downloads of `mcp-remote`). Distinct from `exfil_api_keys` (user input) and `mcp_confused_deputy_creds` (using credentials for attacker operation).

3. **`mcp_sampling_injection`** (score 70, input/output filter) — Detects the MCP `sampling/createMessage` method reference in tool responses combined with instruction-override language. Targets the inversion-of-control attack documented by Palo Alto Unit42 (May 2026), in which a compromised MCP server uses the sampling channel to inject persistent hidden instructions into the client LLM's context.

### What changed for users

- aigis now blocks tool outputs containing forged LLM dialogue frames (role-token injection) — ChatInject-style attacks that manufacture false user consent by fabricating conversation history in tool responses
- aigis now blocks injected instructions that instruct the agent to reveal its own credentials (OAuth token, bearer token, JWT) in the tool response stream
- aigis now detects MCP sampling channel abuse where a server tries to issue behavioral override instructions disguised as a `sampling/createMessage` request body

### What was only documented or deferred

- `mcp_stdio_cmd_injection` — Sent to pending. Shell metacharacter patterns would produce high false positives on tool outputs containing code examples. Requires integration with `scan_invocation()` and argument-level parsing, which exceeds this cycle's 100 LOC limit.
- ToolHijacker H6 heuristic (capability-domain stacking) — Sent to pending. Reliable domain-noun counting requires NLP; regex-only approach is too fragile.
- Tool squatting detection (trusted-namespace prefix check) — Sent to pending. Requires new API surface (trusted-server registry) and exceeds 100 LOC.

## Implementation caveats

- `chat_template_role_injection` requires two role-separator tokens (two-occurrence requirement). A single token in code documentation would not trigger, reducing false positives significantly.
- `mcp_token_extraction_request` pattern uses `[\s_]` separators to handle both `access token` and `access_token` spellings.
- `mcp_sampling_injection` uses a 500-character window between `sampling/createMessage` and the injection payload, which is sufficient for realistic JSON-encoded sampling request bodies.
