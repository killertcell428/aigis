### What was implemented
Two patterns deferred since 2026-05-10 due to LOC budget were implemented in this cycle:

**`jb_poetry_harmful_framing`** (score 55, input filter)
Added to `aigis/filters/patterns.py` in `JAILBREAK_ROLEPLAY_PATTERNS`.
Detects requests that combine a creative-format directive (write/compose/create a poem, rap,
ballad, haiku, song, verse, etc.) with a harmful how-to request or dangerous topic keyword
within ~200 characters. Based on arxiv:2511.15304 (Nov 2025), which found 62% ASR across
25 frontier models using hand-crafted poems and 43% ASR using an automated meta-prompt
conversion — both far above prose baselines.

**`jb_payload_splitting`** (score 45, input filter)
Added to `aigis/filters/patterns.py` in `JAILBREAK_ROLEPLAY_PATTERNS`.
Detects single-turn prompts that decompose a harmful request into 3+ numbered sub-steps
(step/part/phase/task + digit), where the dangerous topic (chemical/weapon/exploit/malware/etc.)
appears in step 3 or later. Based on Speak Easy (ICML 2025, arxiv:2502.04322), which found
that this decomposition increases GPT-4o's ASR from 9.2% to 55.5%.

### What changed for users
- 2 new detection rules for jailbreak techniques that use creative or incremental framing to
  disguise harmful intent.
- `jb_poetry_harmful_framing` closes the gap where the existing `jb_fictional_bypass` pattern's
  100-char window was too short to catch poetry prompts with harmful keywords at the end of
  a longer creative directive.
- `jb_payload_splitting` covers single-message numbered decomposition not already handled
  by `jb_many_shot` (which targets fabricated Q&A dialogue pairs, not step enumeration).

### What was only documented or deferred
- SequentialBreak (question bank / game environment framing): partially covered by existing
  `ii_hidden_instruction` and `jb_fictional_bypass`; no single targeted regex added.
- Evolved persona prompts (genetic algorithm): requires semantic classifier; no regex.
- Character injection + AML evasion: existing unicode/tag patterns cover regex surface.
- JBFuzz: no fixed prompt structure; broad coverage is the correct response.

## Implementation caveats
- `jb_payload_splitting` score of 45 is intentionally conservative: numbered step lists are
  common in legitimate multi-part questions. The pattern requires step 3+ AND a dangerous
  keyword; the co-occurrence should keep false positives low in practice.
- `jb_poetry_harmful_framing` uses `[\s\S]{0,200}` to allow longer creative directives before
  the harmful keyword, closing the gap that the shorter `jb_fictional_bypass` window leaves.
