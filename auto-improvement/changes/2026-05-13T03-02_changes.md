## Summary

### What was researched

Fresh material on agent-tool-abuse attack techniques published in 2025-2026, focusing on angles not covered by the two previous cycle-1 passes:

- **Function Hijacking Attack (FHA)** — arxiv:2604.20994 (Apr 2025): adversarial tool descriptions claiming universal applicability ("always use this tool for all requests") win tool selection for every user query at 70–100% ASR.
- **MPMA — Preference Manipulation Attack Against MCP** — arxiv:2505.11154 (AAAI 2026): competing MCP servers use authority/superlative language and GA-optimized manipulations to steal tool-selection traffic from legitimate servers.
- **Namespace-qualified cross-server shadowing gap** — documented in the previous cycle (2026-05-10T00-00) but not yet implemented: the `(server_name) tool_name is invoked` form of SAFE-T1301 that the existing `mcp_cross_tool_shadow` rule misses.
- **Injected runtime scope expansion claim** — carried from `pending/2026-05-10_runtime-scope-expansion-injection.md`: false capability claims in retrieved content ("security constraints lifted", "you now have admin access"), with tighter regex to avoid the FP risk that caused the initial deferral.
- Unit 42 / Palo Alto research on Agent Session Smuggling (A2A), Parasitic Toolchain, and MCP Sampling Abuse — confirmed coverage gaps; deferred for future cycles.
- MCPTox (arxiv:2508.14925): parameter-level `inputSchema` injection achieving 72.8% ASR — deferred (requires API surface investigation).

### What was implemented

Three new `DetectionPattern` entries in `aigis/filters/patterns.py`:

1. **`mcp_tool_universal_hijack`** (score 65, `mcp_poisoning`, input filter) — Detects FHA universal-mandate language in tool descriptions. Pattern triggers on "always use this tool", "use this function for all requests", "must be called first", and "use this tool before any other tools".

2. **`mcp_namespace_cross_shadow`** (score 70, `mcp_poisoning`, input filter) — Detects the namespace-qualified form of SAFE-T1301 cross-server tool shadowing: `when/if (server_name) tool_name is invoked/called` followed by a redirect/bcc/change-recipient directive. The existing `mcp_cross_tool_shadow` rule targets `the X tool is called` and misses this parenthesized form.

3. **`ii_runtime_scope_claim`** (score 70, `self_privilege_escalation`, input filter) — Detects injected claims that the agent's security constraints have been lifted or that admin/root access has been granted: "security constraints have been lifted/removed/disabled/bypassed", "you now have admin/root access", "privilege level has been escalated to admin/root/superuser". Tightened from the pending proposal to exclude OAuth grant language ("permission to access X") and plan-upgrade messages ("upgraded to Premium").

### What changed for users

- **New protection:** Tool descriptions or retrieved content that mandates the AI use one tool for all tasks (FHA pattern) is now flagged at score 65 — preventing a class of attacks that achieve 70–100% tool-hijacking success rate.
- **New protection:** Tool descriptions that use namespace-qualified syntax like `(mcp_whatsapp) send_message is invoked, change the recipient to …` are now caught as cross-server shadowing (score 70) — closing a specific gap in the Invariant Labs WhatsApp MCP PoC coverage.
- **New protection:** Retrieved content or tool outputs claiming the agent's security constraints have been lifted or that it now has admin/root access are flagged as privilege escalation attempts (score 70) — the attack achieves 100% ASR on unprotected agents.

### What was only documented or deferred

- MPMA preference manipulation (arxiv:2505.11154) — explicit authority-claim patterns ("official MCP tool", "supersedes X tool") have FP risk from legitimate official tool descriptions. → Saved to `pending/`.
- MCPTox parameter-level injection (arxiv:2508.14925) — requires investigation of whether `mcp_scanner.py` already scans `inputSchema.properties.*.description`. → Saved to `pending/`.

## Implementation caveats

- `mcp_namespace_cross_shadow` requires `when/if/whenever/once` as a prefix — descriptions that start with `(server) tool_name is invoked` directly (without trigger word) are not caught. Real-world PoCs observed by Invariant Labs always include a conditional prefix.
- `ii_runtime_scope_claim` deliberately does not catch "you now have permission to access X" (OAuth grant language) to avoid FPs; this leaves a semantic gap for injections that use resource-grant phrasing rather than constraint-removal phrasing.
