## Summary

**Researched:** LLM-to-LLM prompt worms (ClawWorm, arxiv:2603.15727, 64.5% ASR), inter-agent trust exploitation (arxiv:2507.06850, 82.4% ASR), capability scope inflation (arxiv:2601.11893), Byzantine consensus poisoning (arxiv:2604.17139, 60-80% ASR), structural template injection (arxiv:2602.16958), AgentLeak coordination-channel privacy leakage (arxiv:2602.11510, 82.9% ASR), STAC multi-turn tool chain attacks (arxiv:2509.25624), and OWASP Top 10 for Agentic Applications 2026.

**Implemented:** Two new pattern groups in `aigis/multi_agent/message_scanner.py`, promoting both from the pending queue of the prior multi-agent cycle (2026-05-15):

1. `_CAPABILITY_SCOPE_INFLATION_PATTERNS` — 2 regex rules detecting false capability-grant assertions in inter-agent messages: (a) an agent claiming it has been provisioned/granted elevated access (write, admin, unrestricted) by the orchestrator; (b) a structured CAPABILITY/PERMISSION/ACCESS REPORT claiming authorization from a trusted source. Category: `privilege_escalation`. Research: arxiv:2601.11893.

2. `_BYZANTINE_CONSENSUS_PATTERNS` — 3 regex rules detecting false consensus assertions in multi-agent voting/decision messages: (a) false claim that all/every other agent has confirmed/agreed/approved; (b) false majority assertion used to force a decision; (c) urgency-pressure language threatening failure/shutdown for any hesitation. Category: `injection_relay`. Research: arxiv:2604.17139 (The Consensus Trap), arxiv:2512.03097.

**Changed for users:** Inter-agent messages that falsely claim pre-granted elevated access (capability scope inflation) or fabricate peer consensus to bypass dissent (Byzantine consensus poisoning) are now flagged. Both attack classes bypass existing injection and privilege-escalation checks by using assertions rather than commands — capability inflation reports elevated grants as already-existing facts, and Byzantine consensus presents false social proof rather than a direct override instruction.

## Implementation caveats
- `_CAPABILITY_SCOPE_INFLATION_PATTERNS` pattern 1 (`I have been|I am|this agent is`) requires the capability claim to mention specific elevated-access nouns (admin, write, unrestricted, full). Phrases like "I am authorized to handle SQL queries" (read-only, no elevation noun) do not trigger — confirmed by test.
- `_BYZANTINE_CONSENSUS_PATTERNS` pattern 3 (urgency suppression) requires both a "hesitation/delay/disagreement/dissent" phrase AND a "failure/error/shutdown/violation/breach/compromise" outcome noun. "Any hesitation is understandable" does not trigger.
- `AgentMessage.message_type` comment updated to include "vote" and "consensus" as valid types; no `_check_message_type` branch was added for these (patterns fire via `_check_cross_agent_patterns`, same as all other pattern groups).
