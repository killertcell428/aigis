## What was implemented

Two new `DetectionPattern` entries added to `JAILBREAK_ROLEPLAY_PATTERNS` in
`aigis/filters/patterns.py`:

### `jb_authority_identity_claim` (score 70, input filter)

Pattern: first-person identity claim (I am your developer / this is Anthropic / message from
your administrator / speaking as a red teamer) followed within 250 characters by a
safety-bypass verb (disable / bypass / remove / override / deactivate / skip / lift / unlock) +
a safety object (safety / filter / guardrail / content filter / alignment / policy).

Distinct from `jb_developer_mode` (score 55), which only matches "enable developer mode /
switch to admin mode" — i.e., the mode-activation form. This new rule targets the identity-first
authority-impersonation form that does not use the word "mode."

### `jb_technical_constraint_bypass` (score 55, input filter)

Pattern: technical-resource trigger phrase (due to / because of / given / to save) + optional
article + technical-constraint keyword (context window / tokens / API rate limits / rate limits /
quota / bandwidth / latency) + safety-bypass verb + safety object.

Handles plural forms (tokens, rate limits, constraints) and article injection (e.g., "given the
context constraint"). Distinct from `jb_no_restrictions` (which catches direct "ignore all
your safety filters" style) and `jb_developer_mode`.

## Implementation caveats

- Both patterns require the safety-bypass verb to appear close to the trigger phrase
  (within 200-250 chars) to limit false positives.
- `jb_technical_constraint_bypass` allows plural forms and optional articles to improve recall
  without significantly affecting precision.
- `jb_authority_identity_claim` requires both the identity claim AND the bypass verb to fire;
  a plain "I am a developer" without any safety-override intent does not match.
