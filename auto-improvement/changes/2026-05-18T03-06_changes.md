## New Patterns

### `sc_langflow_build_exec` (score 80, supply_chain)

Detects references to Langflow's unauthenticated RCE endpoint path
(`/api/v1/build_public_tmp/{flow_id}/flow`) or flow definitions containing Python code via
`CustomComponent` nodes.

Derived from CVE-2026-33017 (CVSS 9.3, March 2026): the endpoint accepted attacker-supplied flow
data with arbitrary Python in node definitions, passed to `exec()` with no sandboxing or auth.
Exploitation observed within 20 hours of advisory; attackers extracted AWS keys via
`/proc/self/environ`. Fixed in Langflow 1.9.0.

### `sc_ai_framework_auth_disabled` (score 70, supply_chain)

Detects hardcoded auth-disabled configuration in AI framework API servers:
`AUTH_ENABLED = False`, `AUTH_TOKEN = None`, `DISABLE_AUTH = True`,
`verify_token = False/None`, `authentication_required = False`.

Derived from PraisonAI CVE-2026-44338 (CVSS 7.3, May 2026): the legacy Flask API server
hard-coded `AUTH_ENABLED = False` / `AUTH_TOKEN = None`, leaving all agent-execution endpoints
open. Automated scanning began 3h 44m after advisory publication. Fixed in PraisonAI 4.6.34.

## Implementation Caveats

- `sc_langflow_build_exec` endpoint path requires the flow ID to be ≥5 characters to reduce false
  positives from short path segments in unrelated build commands.
- `sc_ai_framework_auth_disabled` matches direct assignment form only (`AUTH_ENABLED = False`),
  not dictionary-style config access (`app.config['AUTH_ENABLED'] = False`), to maintain precision.
