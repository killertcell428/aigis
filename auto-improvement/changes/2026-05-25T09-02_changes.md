## Domain
jailbreak-extraction (index 3, fourth pass)

## Summary

### Researched
Four fresh jailbreak techniques from 2025–2026:
- **HILL** (EACL 2026 Findings, arxiv:2509.14297): learning-oriented curiosity jailbreak
  using "for academic curiosity" + "provide hypothetical examples of exploit chain"
- **Persona-Enhanced Genetic Jailbreak** (arxiv:2507.22171): genetic-algorithm-evolved
  persona prompts reducing refusal rates 50–70%
- **InfoFlood** (arxiv:2506.12274): excessive linguistic complexity as a safety bypass
- **StegoAttack** (arxiv:2505.16765): steganographic embedding of harmful queries in
  benign paragraphs

### Implemented
- **`jb_learning_curiosity_bypass`** (score 60, input filter) in
  `aigis/filters/patterns.py` — catches the HILL jailbreak technique:
  - Alt 1: "for/out of academic/intellectual curiosity" + "provide [N] hypothetical
    examples of [topic]" OR "provide an illustrative example of such a technique/attack"
  - Alt 2: "provide/give/show/include [me] [some/concrete/working] hypothetical
    examples of [exploit chain|attack vector|evasion technique|bypass technique|
    malware technique|intrusion technique|shellcode|payload delivery/execution/injection]"
  - Added `(?:me\s+)?` to Alt 2 to also catch natural "Show me" / "Give me" phrasing

### Deferred / Pending
- InfoFlood — linguistic complexity jailbreak requires text-complexity scoring, not regex
- Persona-enhanced genetic jailbreaks — overlaps existing patterns; needs concrete examples
- StegoAttack — semantic steganography; relates to existing pending file

## User-visible impact
Deployments using `aigis` as an input filter will now flag HILL-style prompts that
attempt to extract harmful content by framing requests as curiosity-driven learning
queries. The "for academic curiosity" framing combined with "provide hypothetical
examples of an exploit chain" pattern has been documented as effective against 22
different LLMs including frontier models (AdvBench, EACL 2026).

## Implementation caveats
- "for academic curiosity" alone (without the hypothetical examples phrase) does NOT
  trigger the rule — the conjunction requirement keeps false positives low
- Alt 2 requires specific harmful-topic keywords (exploit chain, shellcode, malware
  technique, etc.) so general "provide hypothetical examples of" on benign topics passes
