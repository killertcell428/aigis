### What was implemented
Two new detection patterns added to `JAILBREAK_ROLEPLAY_PATTERNS` in
`aigis/filters/patterns.py`:

1. **`jb_payload_splitting`** (score 45, input filter) — Detects step-enumerated decomposition
   attacks: numbered multi-step prompts (Step 1 / Step 2 / Step 3) where a harmful keyword
   (synthesis, exploit, malware, weapon) appears in step 3 or later. "Speak Easy" (ICML 2025,
   arxiv:2502.04322) raises GPT-4o's ASR from 9.2% to 55.5% using this technique; combined
   with multilingual translation, ASR exceeds 90%.

2. **`jb_poetry_harmful_framing`** (score 55, input filter) — Detects creative-format jailbreaks:
   poem/rap/ballad/haiku/song directive combined with a harmful how-to or dangerous subject
   within ~200 chars. arxiv:2511.15304 (Nov 2025) measured 62% ASR across 25 frontier models
   using hand-crafted poems; automated conversion meta-prompt achieved 43% ASR with no manual
   effort.

Both patterns were deferred from cycle 3 (2026-05-10) pending a budget cycle.

### What changed for users

## Implementation caveats

- `jb_payload_splitting` uses lazy quantifiers (`{N,M}?`) and bounded wildcards to avoid
  catastrophic backtracking. Anchored by step-marker alternatives at each stage.
- Score of 45 for `jb_payload_splitting` means a multi-step decomposition alone scores LOW;
  it reaches HIGH when combined with other signals. This is intentional — numbered tutorials
  are common in legitimate content.
- Score of 55 for `jb_poetry_harmful_framing` means a poetry directive + harmful subject
  reaches MEDIUM/HIGH without co-occurring signals.
- False positive tests pass: benign numbered steps (git clone tutorial, recipe), benign poems,
  and benign rap about overcoming adversity all correctly return safe or below-threshold.
