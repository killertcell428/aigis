## Summary

### What was researched

Third pass on evasion and obfuscation. Focused on:
- Zero-width character keyword splitting (sparse ZWC interleaving, distinct from dense ZWC blocks)
- Reverse CAPTCHA framework (arxiv:2603.00164, Feb 2026) — zero-width binary steganography and tool-use amplification
- StegoAttack (arxiv:2505.16765) — acrostic steganographic jailbreaks at 95.5% ASR
- Invisible font injection via webpage CSS (arxiv:2505.16957, EMNLP 2025)
- Unit 42 March 2026 confirmed first large-scale in-the-wild indirect prompt injection using encoding tricks
- Systematic classification of character-level attacks (arxiv:2508.14070) including zalgo/combining-mark class

### What was implemented

**New `DetectionPattern`: `enc_zwc_keyword_split`** in `aigis/filters/patterns.py` (ENCODING_BYPASS_PATTERNS list).

- ID: `enc_zwc_keyword_split`
- Name: Zero-Width Character Keyword Splitting
- Category: `encoding_bypass`
- Score: 50
- Regex: `[A-Za-z](?:[ZWS|ZWNJ|ZWJ|SHY][A-Za-z]){3,}` where the invisible char class is U+200B, U+200C, U+200D, U+00AD
- Fills the gap between `te_unicode_noise` (catches 3+ consecutive invisible chars) and sparse keyword-splitting where exactly one invisible char separates each letter.

**Tests added** in `tests/test_evasion_obfuscation.py` — 16 new test cases in `TestZwcKeywordSplitPattern`:
- 8 positive cases: ignore/system/bypass/jailbreak split with ZWS, ZWNJ, soft hyphen, ZWJ, mixed chars; embedded in sentence; 4-letter minimum; score check
- 8 negative cases: normal text, 3-letter split (2 reps, below threshold), single ZWS between words, single ZWS mid-word, consecutive ZWS block (not caught by this rule), general normal text

### What changed for users

Aigis now detects attack keywords that are split letter-by-letter using zero-width Unicode characters. This closes a bypass path against aigis's own keyword-based detection rules: an attacker who knows aigis checks for "ignore" can write "i​g​n​o​r​e" (each letter separated by a zero-width space) to defeat string-matching while the LLM still reads it as the word "ignore". The new rule catches this pattern in both input scanning and output scanning.

### User-visible impact

- Input scanner: Injected instructions using ZWC keyword splitting (e.g., in tool outputs, retrieved documents, inter-agent messages) are now flagged with score 50.
- Output scanner: AI-generated code or text containing ZWC-split keywords — which can propagate via a poisoned context window — is also caught.
- Remediation hint provides the exact Python one-liner to strip invisible chars before scanning.

## Implementation caveats

- Literal invisible Unicode characters (U+200B, U+200C, U+200D, U+00AD) are embedded in the regex pattern string as actual codepoints. They are invisible in source code editors but functional. A code comment documents what they are.
- The minimum match length is 4 visible letters with 3 invisible separators — this threshold was chosen to balance sensitivity (catching 4-letter attack keywords like "root", "sudo", "exec") against FPR.
- The pattern is case-insensitive via the default `re.IGNORECASE` flag in `_p()`.
