## New Patterns

### `afe_python_mro_escape` (score 80, sandbox_escape)
Detects Python MRO / subclass traversal strings (`__subclasses__()`, `__mro__[N]`,
`().__class__.__mro__`) used to escape eval()-based sandboxes.
Derived from CVE-2026-26030 (CVSS 9.9) in Microsoft Semantic Kernel Python SDK, where
InMemoryVectorStore built lambda filters via `eval()` from user-supplied values; an attacker
smuggled an MRO-traversal payload to reach `os.system()`.

### `afe_agent_memory_file_write` (score 65, memory_poisoning)
Detects instructions to write/modify AI agent persistent memory files by name (SOUL.md,
MEMORY.md, .agent_memory, .agentmem). Derived from the ClawHavoc supply-chain campaign
(February 2026, Koi Security / Antiy Labs): 341–900 malicious OpenClaw skills targeted
these specific files to plant backdoors that survived context resets.

## Caveats

- `afe_agent_memory_file_write` is specific to OpenClaw-style memory file naming; agents
  using different persistent memory file names are not covered. Future cycles could expand
  the pattern as other agent frameworks adopt similar conventions.
- `afe_python_mro_escape` catches `__mro__[N]` indexing patterns; direct attribute access
  without indexing (`cls.__mro__` alone) is not flagged to reduce false positives on
  documentation-style prompts.
