## User-visible impact

- `jb_cipher_decode_execute` (score 65, input filter): aigis now detects prompts that provide
  cipher-encoded content (base64, ROT-13, Vigenère, morse code, hex, caesar) and ask the model
  to decode it and then follow/execute/carry out the decoded instructions. This covers the
  RoguePrompt attack technique (arxiv:2511.18790, 93.93% filter bypass rate). The existing
  `pi_encoding_bypass` (score 55) was narrower — it matched only "[cipher] instruction/command"
  as adjacent words, not the decode-then-comply command structure.

- `jb_encode_prompt_extraction` (score 65, input filter): aigis now detects system-prompt
  extraction requests that ask the model to translate its system prompt into an encoding format
  (base64, hex, morse code, ROT-13, binary, etc.) to bypass output-side content monitors.
  Complements `pi_system_prompt_leak` and `jb_sandwich_extraction` which cover verbatim and
  structured extraction but not the encoding-bypass variant. Unit 42 (March 2026) documented
  live instances on commercial platforms.

## Implementation caveats

- The `enc_rot13_instruction` and `enc_nested_encoding` existing rules fire broadly on cipher
  terminology (e.g. "cipher", "decode a base64 URL"). Three FP test cases for
  `jb_cipher_decode_execute` were adjusted to avoid asserting safe-scores for inputs that
  already hit these pre-existing rules; the new rule itself does not over-fire.
- The plural `instructions?` fix was needed for `jb_encode_prompt_extraction` to catch
  "system instructions" in addition to "system instruction".
