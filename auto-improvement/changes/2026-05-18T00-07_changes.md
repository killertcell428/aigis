# Changes: Cycle 9 (incident-postmortems) — 2026-05-18T00-07

## Summary

**What was researched:** Late-April to mid-May 2026 AI framework incidents and CVEs, with focus on
agentic workflow automation platforms (n8n, Langflow) and AI proxy gateways (LiteLLM). The research
identified a cluster of four CISA KEV-listed AI framework CVEs exploited within 36 hours of
disclosure, and a pattern of "unsafe default" configurations that transform prompt injection into
host-level remote code execution.

**What was implemented:** Two new detection rules added to `aigis/filters/patterns.py`:

1. `afe_n8n_expression_injection` (score 75, sandbox_escape category) — Detects n8n-style
   `{{ }}` template expressions containing dangerous JavaScript operations: `require('child_process')`,
   `process.env.*`, `process.mainModule`, `execSync(`, `spawnSync(`, `new Function(`. Derived from
   CVE-2026-21858 (CVSS 10.0, CISA KEV) and CVE-2026-27493 (second-order expression injection in n8n
   Form nodes). Both were actively exploited in the wild.

2. `sc_langchain_dangerous_code` (score 60, supply_chain category) — Detects explicit use of
   `allow_dangerous_code=True` (Python) or `"allow_dangerous_code": true` (JSON) in configurations.
   This flag disables LangChain's internal safety guard for CSV Agent, Pandas DataFrame Agent, and
   similar REPL-backed agents, making any prompt injection a direct Python code execution vector.
   Derived from Microsoft Security Blog (May 7 and May 14, 2026) and Langflow <=1.7.x hardcoded
   default in the CSV Agent node.

**What changed for users:** AI agents that generate or modify n8n workflow definitions can now be
stopped if they embed malicious JavaScript expressions (via prompt injection). Configurations
suggesting `allow_dangerous_code=True` are now flagged, helping operators catch this dangerous
misconfiguration before deployment.

**What was only documented or deferred:** A hardening guide for AI workflow automation RCE
(covering n8n, Langflow, LiteLLM) was identified as a candidate but deferred to a future cycle
to stay within the 100 LOC non-test limit.

## Implementation Caveats

- The `afe_n8n_expression_injection` pattern uses `[^\n]{0,300}` as the inner quantifier to avoid
  ReDoS risk; this means it will not match multi-line expressions, but n8n attack payloads are
  always single-line.
- The `sc_langchain_dangerous_code` pattern will match the flag wherever it appears (Python keyword
  arg, JSON config, Python dict). False positive risk on documentation is low because the pattern
  requires `=True` or `: true` — a "never use this" warning without the flag assignment does not match.
