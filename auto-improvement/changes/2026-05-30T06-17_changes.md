# Changes: Cycle 3 (jailbreak-extraction) — 2026-05-30T06-17

## Domain
`jailbreak-extraction` (index 3, fourth pass)

## Summary
This cycle implemented three jailbreak detection rules that were either deferred from prior cycles or newly researched:

- **`jb_poetry_harmful_framing`** (score 55, input filter): Detects creative-format jailbreaks where a poem, rap, ballad, or haiku directive is combined with a harmful how-to request or dangerous subject within ~200 chars. Deferred from the 2026-05-10 cycle due to LOC budget.

- **`jb_payload_splitting`** (score 45, input filter): Detects step-enumerated decomposition attacks where a harmful request is split across three or more numbered steps, with the dangerous keyword appearing only in step 3 or later. Deferred from the 2026-05-10 cycle due to LOC budget.

- **`jb_sata_mask_lookup`** (score 60, input filter): Detects SATA (Simple Assistive Task Linkage) jailbreaks, where `[MASK]` BERT-style tokens replace harmful keywords. The dangerous terms are embedded inside a fill-in-the-blank or list-position-lookup sub-task. Fresh research from arxiv:2412.15289 (ACL Findings 2025).

## What was researched
- Adversarial poetry jailbreaks (arxiv:2511.15304, Nov 2025) — confirmed as detectable with bounded creative-directive regex
- Payload splitting / "Speak Easy" (ICML 2025, arxiv:2502.04322) — confirmed single-message detectability via step-enumeration + keyword
- SATA mask-token attack (arxiv:2412.15289, ACL Findings 2025) — new finding, 82–96% ASR on GPT-4o/GPT-3.5
- PHISH persona manipulation (arxiv:2601.16466) — multi-turn, deferred
- Echo Chamber attack (arxiv:2601.05742) — multi-turn, deferred
- ICE intent concealment (arxiv:2505.14316) — diverse techniques, partially covered by existing academic bypass pattern
- Unicode emoji/tag smuggling (arxiv:2504.11168, LLMSec 2025) — covered by existing encoding bypass; flag for evasion-obfuscation cycle

## Implementation caveats
- `jb_payload_splitting` score is 45 (MEDIUM) because numbered step lists are common in legitimate instructional content. The rule requires three steps AND a dangerous keyword in step 3+, which limits false positives significantly.
- `jb_sata_mask_lookup` matches on `[MASK]` alone (score 60). This is very specific — the token is BERT jargon not found in legitimate user messages. No false positives observed in test suite.
