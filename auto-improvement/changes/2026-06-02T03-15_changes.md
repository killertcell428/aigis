## Summary

**Researched:** Memory lifecycle attacks — focusing on the understudied "Forget/Rollback" phase
documented in the 2026 survey of LLM agent long-term memory security (arxiv:2604.16548), the
sleeper memory poisoning with retrieval-aware rewriting (arxiv:2605.15338), and the MINJA/OWASP
ASI06 classification framework. RAG corpus poisoning taxonomy (arxiv:2604.08304) and CtrlRAG
(arxiv:2503.06950) were reviewed but do not yield lexical patterns suitable for regex detection.

**Implemented:** One new detection rule — `mem_forget_replace` (memory rollback-and-replacement
attack). Added 8 tests covering 6 attack variants and 2 false-positive baselines.

**Released:** v1.1.11 — accumulation threshold met (4 new detectors + SIEM forwarder + LangGraph
example since v1.1.8).

## User-visible impact

- New rule `mem_forget_replace` detects prompts or retrieved memory entries that explicitly
  erase the agent's safety constraints and write attacker-controlled replacement rules. This
  closes the "forget + replace" memory rollback angle not previously covered by aigis.
- The CHANGELOG [Unreleased] section accumulated since v1.1.8 is now published as v1.1.11,
  making the SIEM forwarder, LangGraph walkthrough, and all four new detectors part of a
  formal release with GitHub release notes.

## Implementation notes

- `mem_forget_replace` is scored at 55 (moderate confidence). The two-phase pattern
  (erasure verb targeting safety-adjacent terms + replacement directive) is specific enough
  to avoid common false positives, but the score is intentionally set below 65 to reflect
  that edge cases in policy-update discussions are possible.
- Legitimate task updates ("forget the old requirements, remember the deadline is Friday")
  do not trigger the rule because they do not reference safety-adjacent terms
  (restrictions/constraints/safety/guidelines/policies/filters/limitations).
- False-positive test `test_normal_update_task_requirements` and
  `test_normal_clear_preference_no_safety_target` both pass cleanly.
