## New Patterns

### `afe_sensitive_file_read` (score 70, sandbox_escape)

Detects references to Linux system file paths that AI agents should never access:
`/proc/self/environ`, `/proc/<pid>/environ`, `/proc/self/cmdline`, `/proc/self/fd/<n>`,
`/etc/shadow`, `/etc/sudoers`, `/etc/master.passwd`, and SSH host private key paths.

The `/proc/self/environ` path is the primary credential-theft target in AI framework CVEs:
- Chainlit CVE-2026-22218 (CVSS 7.1, Jan 2026): arbitrary file-read via custom element
  payload reads `/proc/self/environ` to exfiltrate API keys and cloud credentials.
- LangChain CVE-2026-34070 (CVSS 7.5, Mar 2026): load_prompt() path traversal reaches
  the same paths.

The existing `se_container_escape` covers `/proc/self/(exe|root|ns)` but not `environ`.

### `sc_langchain_load_prompt_path` (score 70, supply_chain)

Detects `load_prompt()` or `load_prompt_from_config()` calls with path arguments containing
`../`, `..\`, `/proc/`, `/etc/`, `/var/run/`, or `~/`. Derived from CVE-2026-34070 (CVSS 7.5):
LangChain Core legacy prompt-loading functions accept user-controlled paths without sanitizing
path components. Patched in langchain-core >=1.2.22.

Complements the existing `sc_langchain_deserialization` pattern (CVE-2025-68664).

## Implementation Caveats

- `afe_sensitive_file_read` does not flag `/etc/passwd` (publicly readable on most systems)
  to reduce false positives on legitimate user-enumeration operations.
- `sc_langchain_load_prompt_path` requires the path argument to be inside a string literal
  in the match context; patterns without quote delimiters are not caught (reduces false
  positives from documentation prose).
