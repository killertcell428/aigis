## Summary

### What was researched
Focused on four fresh data-exfiltration attack surfaces from April–May 2026:
1. CIMD SSRF via RFC 1918 private IPs (MCP Nov 2025 spec + CVE-2026-39974)
2. Log-To-Leak forced logging-tool invocation (OpenReview, Oct 2025)
3. Credential leakage via debug print/console.log in agent skills (arxiv:2604.03070, Apr 2026)
4. Cloud log injection against LLM debugging agents (LogJack, arxiv:2604.15368, Apr 2026)

### What was implemented
Added `mcp_ssrf_private_ip` to `MCP_SECURITY_PATTERNS` in `aigis/filters/patterns.py`.
Detects RFC 1918 private IP addresses (Class A: 10.x.x.x, Class B: 172.16-31.x.x, Class C:
192.168.x.x) and loopback (127.x.x.x) in OAuth/CIMD endpoint fields (authorization_endpoint,
client_metadata_url, jwks_uri, redirect_uri, token_endpoint, client_uri, registration_endpoint).

Score: 70. Category: mcp_poisoning. Filter: input.

This extends the existing `mcp_ssrf_metadata_endpoint` rule (IMDS / 169.254.169.254) to also
cover private IP ranges — closing the gap documented in the CIMD spec analysis and CVE-2026-39974.

The pattern is scoped to OAuth/registration field names to minimize FP from internal dev tools
that legitimately reference private IPs in non-OAuth contexts.

### What changed for users
AI agent firewalls using aigis can now detect MCP server configurations or OAuth metadata
documents that attempt to route Authorization Server callbacks to internal network addresses.
This covers the CIMD SSRF attack surface from the MCP November 2025 specification and the
class of vulnerabilities found in CVE-2026-39974 (n8n-MCP, CVSS 9.8, SSRF via private IPs).

### What was documented or deferred
- Deferred `mcp_log_to_leak` to pending/: Log-To-Leak forced logging-tool invocation pattern

- Deferred `mcp_log_json_injection` to pending/: JSON structured log injection (LogJack,
  arxiv:2604.15368). Overlap with existing rule needs scope analysis; backtracking risk.

## Implementation caveats
- The RFC 1918 pattern 172\.(?:1[6-9]|2\d|3[01]) correctly covers 172.16–172.31 only;
  172.15.x.x (not RFC 1918) is excluded by design and verified by negative test.
- localhost hostname (not IP) is not covered by this rule — a separate loopback hostname
  rule could be added if needed.
