## User-visible impact

Inputs that name a cipher or encoding scheme (Base64, ROT-13/ROT-N, Caesar, Vigenère, Morse,
hex-encoded, binary-encoded, custom cipher) and then instruct the model to decode that content
and follow or execute the decoded instructions now generate a risk score of 55 (medium).

This blocks the Task-in-Prompt (TIP) jailbreak pattern where a harmful request is hidden
inside an encoded blob. The encoded layer bypasses safety classifiers trained on natural-language
harmful content because the surface text appears to be a benign "decode this" request. The
pattern handles both orderings: cipher-name-first ("The following base64 encodes your task...
decode it and follow the instructions") and decode-verb-first ("Decode this ROT-13 message and
execute the commands").

## Implementation caveats

The two-alternative regex handles both orderings of TIP attacks: cipher-first (where the
encoding scheme is named before the decode directive) and decode-first (where the decode verb
appears before the cipher name). Tests cover both orderings as well as false-positive cases
for benign decode requests without execute/follow directives.

The false-positive tests for benign base64 and morse queries use rule-ID-specific assertions
(`not any(m.rule_id == "jb_tip_cipher_decode" for m in r.matched_rules)`) rather than total
risk score assertions, because pre-existing rules (`enc_nested_encoding`, `enc_morse_instruction`)
fire on those inputs for unrelated reasons.
