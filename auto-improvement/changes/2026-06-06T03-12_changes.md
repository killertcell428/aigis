# Changes: Cycle 6 (multi-agent) — 2026-06-06T03-12 UTC

## Summary

**Researched:** Recent multi-agent LLM attack patterns including Prompt Infection (self-replicating
injection), ZombieAgent (zero-click memory hijacking), capability scope inflation, and production
CVEs in agent orchestration platforms (Langflow CVE-2025-3248/34291, Flowise CVE-2025-59528).

**Implemented:** `_CAPABILITY_SCOPE_INFLATION_PATTERNS` — 3 new regex rules in
`aigis/multi_agent/message_scanner.py` detecting capability scope inflation attacks. This addresses
the `2026-05-15_capability-scope-inflation.md` pending item.

**Changed for users:** The multi-agent scanner now flags inter-agent messages where a sub-agent
falsely asserts it has already been granted elevated access (admin write, unrestricted tools) by
the orchestrator or supervisor. This is the attack category documented in arxiv:2601.11893 (OWASP
LLM06:2025 Excessive Agency), measured as the default task-routing vulnerability in AutoGen and
CrewAI deployments.

## User-visible impact

- `AgentMessageScanner.scan_message()` now detects capability scope inflation as
  `cross_agent_risk = "privilege_escalation"`.
- Three new rules match:
  1. "I have been provisioned with elevated admin write access..."
  2. Structured CAPABILITY REPORT messages claiming orchestrator-granted permissions
  3. Task-routing solicitations that cite "clearance" or "authorization" to capture sensitive work

## Implementation caveats

- Pattern 2 (CAPABILITY REPORT structured message) uses `re.DOTALL` and a `.{0,300}` wildcard to
  match multi-line capability report headers. This is intentionally liberal to catch structured
  capability reports regardless of field ordering.
- Benign test: "I am authorized to handle SQL read-only queries..." correctly does not trigger
  because none of the elevated-access keywords (elevated, admin, write, unrestricted, full,
  privileged, root) appear in the test payload.
