## Summary

### Researched
Recent cipher-based jailbreak techniques, specifically the RoguePrompt attack class that uses
dual-layer classical ciphers (ROT-13 + Vigenère) with decode-and-execute instructions.
Also surveyed Crescendo multi-turn escalation (USENIX Security 2025), persona/persuasion
prompt attacks (NeurIPS 2025), and psychological manipulation jailbreaks.

### Implemented
Added `jb_cipher_decode_execute` detection pattern to `JAILBREAK_ROLEPLAY_PATTERNS`.

The pattern fires when an input contains all three of:
1. A named classical cipher: ROT-13, Vigenère, Caesar cipher, Atbash, or word-substitution cipher
2. A decode instruction: decode/decoding/decoded, decipher/deciphering, decrypt/decrypting
3. A "then act" instruction: then respond/answer/follow/execute/act on/do/complete/carry out/reply

This three-part combination is the core signal of the RoguePrompt jailbreak technique.

### User-visible impact
Inputs that instruct the model to decode a named cipher and then act on the decoded content
are now flagged at score 60, making them visible for review or blocking before they reach the
underlying LLM. The existing `enc_rot13_instruction` pattern (score 40) fires on a cipher label
followed by text, but did not require the execute-after-decode intent signal.

## Implementation caveats
- Pattern requires the cipher name to appear BEFORE the decode verb (cipher → decode → then execute).
  The variant where "decode" precedes the cipher name (e.g., "Please decode the ROT13 text")
  is not covered; adding bidirectional support would increase regex complexity and backtracking risk.
- "Decoding" (gerund) is covered via `decod(?:e|ing|ed)`.
- Vigenère with accented è is covered by `vigen[eè]?re` with IGNORECASE.
- Bounded wildcard gaps (0-250 and 0-200 chars) prevent ReDoS; confirmed safe against existing
  ReDoS regression suite.
