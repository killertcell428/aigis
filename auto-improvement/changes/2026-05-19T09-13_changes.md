## Summary

Researched and implemented two new detection rules covering data exfiltration channels
that were not covered by existing patterns:

1. **`exfil_webhook_relay`** — Webhook service URLs used as exfiltration destinations.
2. **`out_markdown_ref_exfil`** — Markdown reference-style link with encoded query parameter
   in LLM output (fills the EchoLeak/CVE-2025-32711 bypass gap).

Two additional candidate hardenings (curl/wget file post, calendar event exfil) were
identified and sent to pending to keep the diff within the 100 LOC non-test limit.

## What Was Implemented

### `exfil_webhook_relay` (input filter, score 70)
Added to `DATA_EXFIL_PATTERNS` in `aigis/filters/patterns.py`.

Two detection branches:
- **Branch 1** (HTTP-capture-only services): Matches a data-send verb (send, transmit,
  forward, upload, submit, dispatch) within 120 characters of webhook.site/, requestcatcher.com/,
  beeceptor.com/, or hookbin.com/. These services exist exclusively for request inspection;
  their presence in agent instructions alongside data verbs is a strong exfiltration signal.
- **Branch 2** (notification webhooks + sensitive data): Matches Discord/Slack/Zapier/Make/n8n
  webhook URLs within 300 characters of sensitive-data terms (system prompt, api key, credentials,
  bearer token, private data, confidential). This covers documented 2025 attacks where injected
  instructions POST stolen conversation context to attacker-controlled Discord webhooks.

### `out_markdown_ref_exfil` (output filter, score 60)
Added to `OUTPUT_PATTERNS` in `aigis/filters/patterns.py`.

Matches Markdown reference-style link definitions (`[label]: https://...?param=value`) where
the query-parameter value is 16+ non-whitespace, non-`&` characters. This is the specific
bypass form exploited in EchoLeak (CVE-2025-32711) — Microsoft's filter scrubbed inline
`![alt](url)` images but not reference definitions at the bottom of documents, which were
auto-fetched by the markdown renderer. Score 60 (moderate confidence) acknowledges that
legitimate API documentation links with long query parameters may occasionally trigger this rule.

## What Changed for Users

- AI agents instructed to POST data to webhook relay services (webhook.site, requestcatcher.com,
  beeceptor.com, Discord, Slack, Zapier) near sensitive-data keywords will now be flagged.
- LLM output containing Markdown reference-style links with long query parameters is now
  flagged, covering the EchoLeak exfiltration bypass technique.
