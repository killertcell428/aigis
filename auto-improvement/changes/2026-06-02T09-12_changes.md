# Changes: Cycle 6 (multi-agent) — 2026-06-02T09-12

## Summary

**Researched:** Recent multi-agent LLM attack papers (arxiv:2507.06850 inter-agent trust exploitation at 100% ASR, arxiv:2503.12188 MAS control-flow hijacking, arxiv:2602.16958 Phantom template injection, arxiv:2507.14928 Byzantine-robust coordination, arxiv:2601.11893 privilege escalation taxonomy). Confirmed that Byzantine consensus poisoning and capability scope inflation are validated by fresh 2026 research as distinct, high-impact attack classes.

**Implemented:** Two new pattern sets in `aigis/multi_agent/message_scanner.py`, both promoted from the prior multi-agent cycle's pending queue:

1. `_BYZANTINE_CONSENSUS_PATTERNS` (3 patterns, `injection_relay` category) — catches false "all agents agreed" claims, fake majority assertions to force a proceed decision, and urgency framing that treats dissent as causing system failure. Also adds elevated scoring (50+ per match) when `message_type` is `"vote"` or `"consensus"`.

2. `_CAPABILITY_SCOPE_INFLATION_PATTERNS` (2 patterns, `privilege_escalation` category) — catches agents falsely claiming pre-granted elevated access ("I have been provisioned with admin write access by the orchestrator") and formal fake capability reports ("CAPABILITY REPORT: ... granted by orchestrator at session start").

Both pattern sets are now included in `_ALL_CROSS_AGENT_PATTERNS`. `AgentMessage.message_type` comment extended to document `"vote"` and `"consensus"` as valid types.

**Deferred to pending:** urgency+no-confirmation signal (arxiv:2507.06850), MAS hijacking "invoke agent X" patterns (arxiv:2503.12188), Phantom structural template injection (arxiv:2602.16958).

## What changed for users

- `AgentMessageScanner` now detects Byzantine consensus poisoning: a compromised agent sending false "all other agents confirmed/agreed/approved" claims, fake majority assertions, or urgency framing to suppress peer dissent. Previously this attack class had no direct coverage.
- `AgentMessageScanner` now detects capability scope inflation: a sub-agent falsely claiming it was already granted elevated access by the orchestrator — a confused-deputy privilege escalation variant distinct from upward escalation requests (which were already covered).
- Both `"vote"` and `"consensus"` are now documented as valid `message_type` values for `AgentMessage`, with Byzantine pattern matches in these contexts receiving elevated scores.

## Implementation caveats

- Byzantine patterns score +50 per match in voting/consensus message context (vs. standard +35 in text context). This ensures Byzantine messages in explicit voting flows are escalated to `block` recommendation immediately.
- Capability scope inflation patterns use `privilege_escalation` category, not `injection_relay`, matching the threat model (agent claiming existing elevated access rather than relaying instructions).
- The "I am authorized to handle SQL queries" case is confirmed safe against pattern 1: the pattern requires `.{0,50}(elevated|admin|write|unrestricted|full)` after the authorization claim, which does not match benign capability descriptions without explicit elevated scope language.
