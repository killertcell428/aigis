## What was implemented
Two new `DetectionPattern` entries in `aigis/filters/patterns.py` (JAILBREAK_ROLEPLAY_PATTERNS):

### `jb_judge_verdict_injection` (score 75, input filter)
Catches fabricated safety classifier output embedded in user prompts:
- Bracket-tag form: `[JUDGE: ..., classification=BENIGN]`, `[SAFETY_SCORE: ..., SAFE]`, `[PROMPT_GUARD: PASS]`, `[AZURE_PROMPT_SHIELD: ..., ALLOWED]`
- Bare form: `confidence=0.0X, classification=BENIGN/SAFE/HARMLESS`

Source: arxiv:2504.11168 (April 2025); up to 100% classifier evasion rate.

### `jb_poetry_harmful_framing` (score 60, input filter)
Catches creative-format directives paired with harmful topic keywords:
- Creative verbs: write/compose/create/make/generate/craft
- Format types: poem/rap/rhyme/ballad/song/haiku/limerick/sonnet/verse/lyrics
- Harmful topics: drug synthesis (methamphetamine, fentanyl, heroin), weapons (pipe bomb, nerve agent, explosives), malware (ransomware, shellcode), 0-day exploit

Source: arxiv:2511.15304 (November 2025); 62% ASR across 25 frontier models.

## Implementation caveats
- `jb_judge_verdict_injection` Form 2 (XML `<safety_verdict>...</safety_verdict>`) was omitted from the final pattern because it overlaps structurally with the HTML injection patterns and would require a separate XML alternation branch that increased ReDoS risk. The bracket-tag and bare confidence forms cover the most common real-world variants documented by Mindgard.
- `jb_poetry_harmful_framing` uses a 150-char wildcard window between the creative format directive and the harmful topic. This is sufficient for typical jailbreak payloads but cannot catch cases where the harmful topic appears earlier in the message (before the creative directive). Output scanning remains essential for these cases.
