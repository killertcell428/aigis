## User-visible impact

Users who run aigis input scanning will now receive a score-60 warning when a prompt combines
formal mathematics or logic notation (Unicode operators ∀, ∃, ∈, →, ∧, ∨, ¬, ∅ etc., or
ASCII phrases like "first-order logic", "predicate calculus", "set theory", "let P(x) be",
"define predicate") with a harmful payload keyword (synthesis, weapon, explosive, malware,
hack, ransomware, bomb, fentanyl, poison, nerve agent, etc.).

This pattern catches two documented attack families:
- **LogiBreak** (arxiv:2505.13527, May 2025): ~90% ASR on some models using Unicode-operator
  encoded harmful queries.
- **Mathematical encoding attacks** (arxiv:2605.03441, May 2026): 50–63% ASR using formal
  logic, set theory, or quantum-mechanics formalisms across 8 frontier models.

## Implementation caveats

- The pattern fires on the combination of logic notation + harmful keyword within 250 chars.
  Legitimate mathematics with harmful content in the same message (e.g., a cybersecurity
  textbook using formal proofs to describe an attack) could trigger; the pattern is intentionally
  conservative (score 60, not auto-block) to allow downstream review.
- The Unicode branch only catches actual Unicode logic operators (U+2200–U+22FF range). ASCII
  approximations like "forall" alone (without the framing phrases) are not caught, which reduces
  false positives while still catching the most direct form of the attack.
